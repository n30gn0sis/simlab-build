## Findings

1. **Docker's image store is not on the Docker volume. Open, for a decision.**
   - **What was measured:** this Docker (29, a fresh install) runs the containerd snapshotter. Images live in `/var/lib/containerd`, on the **root** filesystem: 25G there, against 232K in `/var/lib/docker`.
   - **Why it matters:** the kit's `preflight`/`docker` guard ("`/var/lib/docker` is its own mount") passes while every `docker load` fills the root filesystem, the failure that guard exists to prevent. A fresh install on the R770 is likely to default to the same store.
   - **The options:**
     - put `/var/lib/containerd` on the Docker volume, or give it its own volume (buildout §3.2, Phase 3);
     - turn the containerd image store off in `daemon.json` at the kit's `docker` step;
     - have the kit's guard check where images actually land.
2. **The scenario names moved to a `.lab` zone** (`scenario.lab`), because the kit's no-internet rule allows only loopback or `.lab` names. The kit's guard now allows a `.lab` URL only when `curl --resolve` pins it to a lab-range address.
